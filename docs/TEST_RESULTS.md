- 规则 20/100/200 Hz、抖动、长间隙、低控制频率、重复/回退存储时间、缺失/回退 header 和收包延迟均命中预期规则。
- TF 多父节点、环、不连通、静态外参变化、短录制大跳变、平移/旋转突变、速度尖峰、断档、时间回退、零/非单位四元数均有独立断言。
- IMU、LaserScan、PointCloud2、Livox、Image、Odometry、JointState、NavSatFix、BatteryState 和 DiagnosticArray 的正常/无效/空帧/冻结/饱和/低电量/过温/硬件告警路径均通过。
- ROS1、独立 MCAP、MCAP 多分片、SQLite 多分片、zstd 文件压缩、zstd 消息压缩均由运行时生成的真实 bag 读写验证，不是伪造 JSON。
- 损坏 ROS1、SQLite、MCAP、缺失分片、错误扩展名、非法阈值和缺失 setup 均稳定失败；开启 `ResourceWarning` 即错误模式后也没有遗留文件句柄。
- 回放脚本对包含中文、空格、分号和方括号的路径保持单参数传递；无命令拼接，诊断和报告写入不修改 bag。

## 8. 失败路径与安全性

已执行的主要故障注入包括：

- 不存在、错误扩展名、截断、少于 3 点、缺少 XYZ 和包含 NaN/Inf 的 PCD。
- PLY/MAP BIN/OLX 的错误魔数、截断帧头、截断点记录、15/16 B 步长、非有限点、缺失/损坏配套文件。
- 损坏 JSON、错误格式、非整数/未来版本、丢失基准点云、区域伴随文件或第二点云。
- 相对路径移动恢复、v1–v6 旧工程、`.odinpcd` 兼容、最多 200 条分析记录恢复限制。
- 零长度、重复点、共线、自交、边界点、凹多边形、垂直平面和极端网格尺寸。
- ICP 无重叠、尺度错误、过大体素、迭代 1/上限、距离阈值端点。
- 目标是目录、临时文件无法提交和派生伴随文件中途失败；失败后不报伪成功、不用半文件覆盖旧输出。
- 忙碌期二次加载、100 步历史上限、redo 分支清理、无效标注导入和最近文件去重/过期清理。
- 空 bag、损坏/截断存储、metadata 计数不符、缺失多分片、没有自定义消息类型、未安装可选 reader、非法诊断阈值和报告目标不可写。
- QoS 缺少订阅端、消息没有发布序号以及正常运动造成 TF 位移等不可离线确定的情况，在报告中明确标记结论边界，避免伪造“确定丢包”或“确定 QoS 不匹配”。
- 诊断只以只读 SQLite URI 或 reader 打开源 bag；真实 bag 诊断前后消息数和源文件未改变。

## 9. 仍需在新电脑上做的安装检查

代码层和隔离桌面目录安装已自动通过。Ubuntu 桌面对第一次双击 `.desktop` 的“允许启动/信任”是操作系统安全策略，无法由应用程序强制绕过。在新机器首装时，按 README 右键图标选择“允许启动”，再执行一次双击启动即可。

测量结果的算法一致性已测试；但与卷尺、全站仪等现场真值的最终差异，仍由传感器标定、SLAM 漂移、点云分辨率和人工选点共同决定。ROS bag 回放还依赖新电脑上安装的 ROS 版本、storage 插件及自定义消息工作空间；离线诊断会在这些依赖缺失时给出降级说明。
